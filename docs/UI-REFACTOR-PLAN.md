# BossHunter 面板重构记录

> 目标：把"不方便、不简单、不直觉"从信息架构层面解决，而不只是换个文案。
> 范围：`src/content/panel.ts`、`src/content/index.ts`、`src/content/ui/styles.ts`、`src/lib/{types,config,safety}.ts`。
> 状态：下列改动均已实现，并通过 `npm run verify`（无头 Chrome 逐帧断言）与 `npm run build`。

## 0. 变更概览

- **P0**：假承诺文案、投递确认层、设置页真取消、预览去重、计数口径统一。
- **动画/交互修复**，由无头 Chrome 逐帧实测驱动：
  | 缺陷 | 实测证据 | 修复 |
  |---|---|---|
  | 设置分组展开/收起无动画 | `gridTemplateRows` 任何状态恒为 `154px`；`<details>` 在新版 Chrome 用 `content-visibility` 隐藏内容，使 grid 折叠失效 | 改为普通 `div`+`button`+CSS `grid-template-rows 0fr↔1fr`（无 JS 手算高度）；实测展开/收起各 15~16 个中间帧、无回抽 |
  | **高度过渡「抽风」（关键）** | 多处"双重高度动画"叠加：①分组 body 自己过渡 + root 又补间一次 → 收起时先塌到 299 再爬回 1349 又砸到 1219；②切设置页时量高度时工作台还没收完（差 228px）→ 目标偏大 → 过渡到 1449 再砸回 1219 | **单一动画源**：分组只由 CSS grid 过渡；切设置页时**工作台自己 `grid 1fr→0fr` 做收起动画**（不是一帧 display:none），root 为 auto 高度自然跟随，不再由 JS 强设高度；实测工作台收起 228→185→…→0 共 17 帧、root 0 次方向反转 |
  | 进设置页高度二次跳变 | 777→377→881，单帧最大跳 504px（`openSettings` 异步渲染晚于量高） | 预设初始化改用 `BUILTIN_PRESETS` 同步渲染；实测单调不回弹 |
  | 确认层无焦点管理 | 打开后 `activeElement=BODY`；Esc/点遮罩都不关；Tab 漏到背后按钮 | 打开聚焦安全项、Esc/遮罩关闭、Tab 焦点陷阱 |
  | 确认层退出瞬隐 | 退出帧全为 `none:1` | 新增 `closing` 退场动画，`animationend` 后隐藏 |
- **P1**：九段手风琴 + 调度参数收进「高级设置」，默认路径零数字输入。
  - 设置页默认只展开「关键词 / 薪资」；「节奏 / 上限 / 招呼语」合并进一个默认折叠、虚线框的「高级设置」容器（带「已有合理默认值，一般不用改」引导）。
  - 实测：默认路径可见数字输入框 = **0**；「预设方案」默认收起，把第一屏让给真正的筛选条件。
- **控件重设计**：原来 6 个调度数值都是「纯输入框」，用户必须敲数字。现改为**滑块 + 可编辑数值气泡**：
  - 拖动 / 滚轮 / 方向键均可快速调；右侧数值可直接点开精调，滑块与输入框双向同步。
  - 每个数值占一整行（滑块靠左、数值气泡靠右、两端给出量程），比原来两列挤在一起更清晰。
  - 量程按语义设定：每轮 1–50 条、加载 0–10 页、轮间隔 30–600 秒、条间隔 3–120 秒、每日上限 10–300、目标 5–200（间隔下限即平台安全下限）。
  - 输入框改为与滑块 step 对齐（如步长 5，输入 77 会吸附到 75），避免"数字 77 / 滑块 75"的不一致。
  - 应用预设时会同步更新滑块位置与填充色。
- **高级设置默认值 + 平台安全下限**：
  - 新增 `src/lib/safety.ts`：`SAFETY`（硬边界）+ `RECOMMENDED_ADVANCED`（推荐起点）。间隔类安全下限：**每条 ≥ 3 秒、轮间隔 ≥ 30 秒**；上限：每条 ≤120 秒、轮 ≤600 秒；数量类也各有上下限。
  - 滑块与输入框的 `min/max` 直接取自 `SAFETY`，越界输入会被夹回；`normalizeConfig` 与 `readFormIntoConfig` 双重夹取，旧数据/手改也无法突破。
  - 高级设置顶部新增「**保存为默认** / **恢复默认**」：把当前节奏与上限存进 `cfg.advancedDefaults`（持久化到 storage）；恢复时优先用自定义默认，没存过则回退 `RECOMMENDED_ADVANCED`。
  - 每个间隔字段下方直接写明安全下限（如「轮间隔不得低于 30 秒，更低容易被平台判定为脚本」）。

## 1. 根因诊断

一句话：

> **这个面板把一个"常驻的实时页面过滤器"和一个"一次性群发机器人"焊在了同一屏上，再用「1 筛选 / 2 确认 / 3 投递」三步向导假装它是线性的。**

三步向导暗示"按顺序走完就结束了"，但第 1 步不是一步，是一个**一直开着的模式**：`MutationObserver` 每 400ms 重算一次，把不通过的卡片直接 `display:none` 藏掉（`BUSINESS-FLOW.md §3.1`）。用户以为在走流程，实际脚下一直在被改页面。

由此派生两个结构性后果：

- **默认路径太长**：想投出第一条消息，必须先理解 9 个折叠区 + 8 个调度控件。这是"配置一台投递机"，不是"帮我投几个"。
- **重动作没有闸门**：唯一真正不可逆的动作（给真人 BOSS 发消息）零确认；而 reversible 的动作（改表单）反倒给了个假「取消」。

所以"不简单"不是功能多，是**该默认的没默认，该收起的没收起，该拦的没拦**。

## 3. 新的信息架构

放弃"三步向导"，改成**一个默认动作 + 两层退路**：

```
┌─ 面板打开 ─────────────────────────────┐
│                                        │
│  ① 默认视图（不需要学习）               │
│     找到 N 个符合"前端实习"的职位        │
│     [  投递这 N 个  ]  ← 唯一主按钮     │
│     想调整？→「筛选条件」                │
│                                        │
│  ② 筛选层（用户主动进入才出现）          │
│     条件分组，默认只展开"关键词"         │
│     ── 高级设置（折叠）──                │
│        节奏 / 上限 / 目标 / 招呼语       │
│                                        │
│  ③ 确认层（投递前的闸门，必经）          │
│     将向 N 家公司发送消息                │
│     招呼语预览 · 预计耗时 · 今日 3/120   │
│     [ 确认发送 ]   [ 再看看名单 ]        │
└────────────────────────────────────────┘
```

三处核心变化：

1. **筛选语义显性化**：面板顶部只留一句人话——「正在按 *前端实习* 过滤页面，隐藏了 122 个职位」，让"页面被改"这件事可见、可关。
2. **调度全部下沉**：8 个调度控件 + 招呼语 + 上限目标收进「高级设置」，全部有可用默认值（`targetCount 20` / `roundSize 5` / 间隔 5s、60s），**默认路径上不出现任何一个需要用户填的数字**。
3. **投递必经确认**：主按钮 → 确认层 → 才真正 `runBatch()`。

## 4. 关键界面 Before / After

### 4.1 预览页顶部（数字口径统一）

**Before**
```
5 个可投 · 共 128 个职位            [已筛选]
已筛出 6 个，确认名单后即可开始投递。
[ ▶ 开始投递 5 个 ]
[筛选条件][刷新][查看更多][显示全部]
● 接口数据：共 128 个，保留 6 个
```

**After**
```
按「前端实习」筛选 · 页面上共 128 个
符合 6 个，其中 5 个可投（1 个你已排除）
[ ▶ 投递这 5 个 ]
[ 调整筛选 ]  [ 再看 122 个 ]
```

规则：**一个数字只出现一次主语**。同一集合用一个词，并给出"为什么是 5 不是 6"的即时解释，而不是让用户自己推。

### 4.2 术语对照表（全量替换）

| 现在 | 改为 | 理由 |
|---|---|---|
| 接口数据：共 N 个 | 页面上共 N 个 | 用户不关心数据从哪来 |
| 保留 / 可投 / 筛选通过 | 符合条件 / 可投递 | 收敛为两个概念 |
| 卡片 / 尚未渲染出卡片 | 职位列表还没显示出来 | 实现细节不外泄 |
| 待重试队列 | 这些没发出去 | 说结果，不说机制 |
| 额外加载页数 | （收进高级，删除此项外露） | 无人能理解 |
| 刷新 / 查看更多 / 显示全部 | 重新扫描 / 多找一些 / 暂时显示全部 | 动词区分 |
| 只留命中 / 剔除命中 | 必须包含 / 一律不要 | 去掉双重否定 |
| 填写即生效 | （删除，改为未保存时顶部出现"有未保存的修改"提示条） | 不承诺不存在的行为 |
| 取消（设置页） | 返回 / 放弃修改（二选一，见 §6） | 名实相符 |

### 4.3 投递确认层（新增，最高优先级）

```
┌──────────────────────────────────┐
│ 确认投递                          │
│                                  │
│ 将向 5 家公司的 BOSS 发送消息      │
│ 招呼语：您好，我对 UE开发工程师很   │
│        感兴趣，方便进一步沟通吗？  │
│ 预计耗时：约 2 分 30 秒（每条 5 秒）│
│ 今日已投：3 / 120                 │
│                                  │
│ [ 确认发送 ]        [ 再看名单 ]   │
└──────────────────────────────────┘
```

只在这一处保留"机器参数"（预计耗时），因为此刻它才是用户真正关心的信息。

## 6. 已确定的交互约定

1. **设置页底部按钮**：无未保存改动显示「返回」，一旦改动显示「放弃修改」（红色），点击后重渲染还原。
2. **「不筛选也能投全部」保留**：但确认层会显示红色警告「你还没有设置任何筛选条件，这会把页面上的全部 N 个职位都投一遍」，并把确认按钮转为危险色。

## 7. 明确不做的事（anti-goals）

- **不换视觉语言**。现有 token（`--bh-s1..s5`、`--bh-brand`）、动效、暗色日志区都是合格资产，本次只动信息架构和措辞。
- **不删功能**。所有筛选能力保留，只是重新分层。
- **不改与宿主页面的共存机制**（顶部栏避让、滚动隔离、让位宽度）——这块已经打磨得很好。
- **不引入 UI 框架**。继续用原生 DOM，保持扩展体积与注入稳定性。

---

## 8. 一句话总结

把"三步向导"降级成"一个默认动作 + 一层可选筛选 + 一道投递确认"，把机器参数全部下沉到默认看不见的地方——**用户只需要回答"投不投"，而不是"这台机器怎么配"**。

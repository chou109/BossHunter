# BossHunter - Boss猎手

> BOSS直聘 网页端增强工具 Chrome 扩展 · 批量投递 · 自动打招呼 · 精细筛选 · Boss活跃细分

BossHunter（Boss猎手）是一个针对 [BOSS直聘](https://www.zhipin.com/) 网页端的 Chrome 扩展，它在职位列表页右侧注入一个悬浮控制面板，帮你把网页端缺失、而移动端独有的能力补回来：**批量投递、日薪/时薪/月薪金额筛选、Boss 活跃状态细分**等。

---

## ✨ 功能亮点

### 1. 批量投递（立即沟通）
- 一键对**筛选通过**的职位逐个点击「立即沟通」，自动处理**发送成功 / 确认弹窗 / 已达沟通上限**三种情况
- **分轮调度**：每轮 `roundSize` 个，条与条、轮与轮之间可设**固定或区间随机**的间隔，贴近真人节奏，降低风控概率
- 可设**每日上限 `deliveryLimit`**、**目标数量 `targetCount`**，够数即停
- 支持**暂停 / 继续 / 终止**；失败职位自动进入**重试队列**，可在预览页逐条重试
- 自动打招呼（可配模板，支持 `{{jobName}}` / `{{company}}` / `{{bossName}}` 占位符）

### 2. 精细筛选（网页端缺失，移动端独有）
- **薪资金额筛选**：日薪（元/天）、时薪（元/时）、月薪（K），下拉选档（如 `200元/天以上`）
  - 勾选「**只要薪资包含设置金额即可**」= 职位薪资区间覆盖该金额即通过（如 150-250 对 200 也过）
  - 默认（不勾）= 职位**最低薪资须达到设置金额**（整段落档）
- **Boss 活跃状态细分**：不限 / 刚刚 / 今日 / 3日内 / 本周 / 本月 —— 与移动端一致，可提前避开长期不活跃的 Boss
- 职位名 / 公司名 / 标签技能关键词（每行一组，空格分隔=需全部命中；可"只留命中"或"剔除命中"）
- **排除关键词**：职位名 / 公司名 / 职位描述 / 标签技能，含任一即剔除
- 其他：剔除面议、剔猎头、剔金牌面试官、剔已沟通/好友、仅 Boss 在线、工作经验、仅保留实习生

### 3. 规避 BOSS 反爬混淆
BOSS 用自定义字体把薪资数字渲染成乱码，直接读 DOM **解析不出数字**。BossHunter 通过在页面主世界（`world: 'MAIN'`）注入网络 hook（`networkHook.ts`），捕获接口返回的**真实薪资（lowSalary/highSalary）** 和 **Boss 活跃时间**，并按 `encryptJobId` 与卡片精确配对，从而让日薪金额、活跃细分真正生效。解析不出数字时**不误删**，只放行。

### 4. 悬浮面板（三页签）
- **预览**：实时名单「可投递 (N)」，**点任意一条即把宿主列表滚动到该职位在列表里的位置并高亮**（也可用键盘 Tab 聚焦后按 Enter），每条还可单独「排除」
- **日志**：实时运行日志（info/ok/warn 着色）
- **设置**：全部筛选条件可视化配置；投递节奏 / 上限 / 招呼语集中在默认折叠的「高级设置」里，点「保存并筛选」才生效
- 附加：**看全部**（临时展开，不会被列表刷新吞掉）、**多找一些**（滚/拉更多职位）、**重新扫描**（重读当前列表）、**调试**（导出诊断数据方便排查）

## 🚀 部署（安装）

### 环境要求
- **Node.js ≥ 18**（推荐 20 / 22）
- npm（或 pnpm / yarn）

### 1. 安装依赖
```bash
npm install
```

### 2. 构建
```bash
npm run build
```
产物输出到 `dist/` 目录（含 `manifest.json`，是标准 MV3 已解压扩展结构）。

> 只跳过 TS 类型检查快速构建可用 `npm run build:only`。

### 3. 加载到 Chrome
1. 打开 Chrome，地址栏访问 `chrome://extensions`
2. 打开右上角**「开发者模式」**开关
3. 点**「加载已解压的扩展程序」**
4. 选择本项目的 **`dist`** 文件夹

加载成功后，打开 BOSS直聘职位列表页，页面右下角会出现 `BH` 悬浮按钮，点开即是完整控制面板。

## 🛠 调试 / 开发

### 开发模式（自动重建）

```bash
npm run watch
```

改完代码后自动重建 `dist/`（约 1–2 秒），终端会提示构建结果；你只需去扩展页点一次「重新加载」，再刷新 zhipin 页面。

```text
16:16:44 ✓ 已重建 (1314ms) · content\ui\styles.ts
         → 到扩展页点一次「重新加载」，再刷新 zhipin 页面
```

构建失败时会直接打印出错文件与行号，修好后自动恢复，不需要重启监听。

> **关于 `npm run dev`**：CRXJS 的 dev 模式让页面从 Vite dev server 动态 `import` 模块，但 content script 运行在 `zhipin.com` 页面里，跨源 + 扩展 CSP 下容易加载失败（实测该模式下扩展连 service worker 都起不来、面板不注入）。而 Vite 自带的 HMR 对 content script 只能整页 reload，收益有限。因此推荐 `npm run watch`：产物与正式包完全一致，稳定可靠。

### 常用命令
| 命令 | 作用 |
|---|---|
| `npm run watch` | **推荐**：监听源码，改动后自动重建 `dist/` |
| `npm run dev` | Vite dev server（端口 5173，见上方说明） |
| `npm run build` | 类型检查 + 生产构建到 `dist/` |
| `npm run build:only` | 仅构建，跳过 `tsc` 检查 |
| `npm run verify` | 无头 Chrome 复验面板行为并更新 `docs/shots/` |
| `npm run preview` | 预览构建产物 |

### 面板「调试」按钮
职位读不到、数据对不上、薪资筛不出来时，点面板的**「调试」**，它会复制一份诊断数据到剪贴板，方便排查。内容包含：

- **顶部固定栏诊断**：视口尺寸、`body` 让位宽度、面板当前 `top` 与紧凑模式状态，以及页面上**所有 fixed/sticky 元素**的 tag/class/top/bottom/宽高/z-index
- Vue 内部 `jobList`、卡片 HTML、右侧详情面板、官方筛选栏、网络捕获的接口数据

> 面板定位不准（偏高/偏低/遮挡头像）时，把「顶部固定栏诊断」那一段贴出来即可定位。

### 面板行为复验
```bash
npm run verify
```
用无头 Chrome 打开 `dev-harness/` 里的仿真页（加载**真实的 Panel 类**），验证并输出：

- 5 个界面状态的渲染
- 设置页工作台收起动效是否连续
- 投递按钮 / 工具栏 / 状态行是否被压扁
- 顶部固定栏避让是否只避开「主顶栏」而不误算筛选栏
- 面板内滚动是否带动宿主页面

截图写入 `docs/shots/`。**注意**：它验证的是面板自身行为，不代表在真实 BOSS 页面上的表现——宿主结构差异仍需在真机确认。

```bash
npm run test:presets   # 预设：内置预置、应用回填、自定义保存/删除
npm run test:apply     # 投递流程：不跳聊天页、不误点「继续沟通」
```

## 📖 操作方法（快速上手）

1. **打开职位列表页**（如 `https://www.zhipin.com/web/geek/jobs`），点页面右下角 `BH` 展开悬浮面板
2. **设置** → 可直接用**预设方案**一键套用，或手动配置筛选条件（投递节奏等机器参数在「高级设置」里，已有安全默认值）
3. 点**「保存并筛选」**——列表按条件隐藏不匹配的卡片，预览栏给出可投递数量（可通过「多找一些」加载更多职位补足）
4. 若有不合意的职位，在**预览**里点该条「排除」
5. 点**「投递这 N 个」**→ 在弹出的**确认层**里核对"发给谁、发什么招呼语、预计多久"，点**「确认发送」**后才会真正开始；过程中可**暂停 / 继续 / 终止**
6. 任务结束可在**日志**查看结果，未确认发送的职位可回**预览**逐条「重试」

> **平台安全**：为避免被 BOSS 判定为脚本，投递间隔有硬性安全下限（每条 ≥ 3 秒、轮与轮 ≥ 30 秒），界面会拦截更小的值；「高级设置」里可把常用节奏「保存为默认」，之后一键「恢复默认」。

### 筛选预设

**设置 → 预设方案**：

- **内置预设**「前端开发 · 实习向」：12 个职位关键词、34 个排除词、日薪 ≥200、月薪 ≥4K、3 日内活跃、每轮 20 条、轮间隔 60–240s、每条 15–40s、每日上限 200、目标 150
- 点**「应用」**把预设填进表单 → 再点**「保存并筛选」**才真正生效（避免误改当前配置）
- 配好一套条件后，在「保存当前」输入名字即可**存成自己的预设**，可随时复用或删除
- 预设存在 `chrome.storage.local`，与配置分开存放，不影响职位列表

> 预设只保存 **筛选条件 + 投递节奏 + 上限目标**，不含运行期状态（已排除的职位、重试队列等）。
6. 任务结束可在**日志**查看结果，未确认发送的职位可回**预览**逐条「重试」

## 🏗 技术架构

| 模块 | 文件 | 说明 |
|---|---|---|
| 类型与默认配置 | `src/lib/types.ts` | `AppConfig` / `FilterConfig` / `RangeSetting` 等 + `DEFAULT_CONFIG` + `STORAGE_KEY` |
| 配置存取 | `src/lib/config.ts` | `loadConfig` / `saveConfig` / `onConfigChanged`（`deepMerge` 默认值兜底） |
| 筛选主逻辑 | `src/lib/filter.ts` | `passFilter()` 依次执行关键词/薪资/活跃/经验等 |
| 薪资解析 | `src/lib/range.ts` | `parseRange` / `salaryUnit` / `matchRange` |
| 活跃归类 | `src/lib/activity.ts` | `classifyActiveText` / `classifyActiveTime` / `activeWithin` |
| 核心逻辑 | `src/content/index.ts` | 数据采集、过滤、批量投递、悬浮面板回调 |
| 悬浮面板 UI | `src/content/panel.ts` | 注入页面右下角的三页签控制面板（原生 DOM） |
| 网络 hook | `src/content/networkHook.ts` | 以 `world:'MAIN'` + `document_start` 注入，捕获真实薪资/活跃接口 |
| 弹窗设置 | `src/popup/` | Vue 3 精简设置入口（完整功能在页面内悬浮面板） |
| 后台 | `src/background/index.ts` | 系统通知扩展点 |

**技术栈**：TypeScript 5 · Vue 3（仅 popup）· Vite 6 · @crxjs/vite-plugin 2 · Manifest V3

**关键机制**
- **双内容脚本**：`index.ts`（document_idle，isolated world）负责操控页面；`networkHook.ts`（document_start，MAIN world）负责抓接口数据，二者通过 `window.postMessage` 通信，规避扩展 CSP 与页面沙箱限制
- **卡片↔接口配对**：优先按 `encryptJobId` 从 `a[href*="job_detail"]`/DOM 匹配，拿真实薪资与活跃状态
- **薪资混淆对策**："解析不出即放行"，绝不误删；真实筛选依赖接口捕获数据

- `notifications`：可选的系统通知扩展点

## 📝 常见问题
- **职位一加载就没了**：是被筛选隐藏了，点「看全部」临时恢复；重新「保存并筛选」恢复过滤。
- **目标设了 150，怎么只加载到几十个（比如 43）？** 分两层：
  1. **总数**（接口池里抓到的职位）会被「接口翻页」补到好几页。以前这里有个 bug：BOSS 的 `joblist.json` 很多响应根本没有 `hasMore` 字段，旧代码 `if (!hasMore) break` 把 `undefined` 当成“没有更多”，于是翻到第 2 页就停（约 30 个）。现已改成“缺省视为还有更多”，靠**空页 / 连续重复页**判断真正到底，并会把“翻了几页、为什么停”写进日志。
  2. **符合数**（筛选通过的）本来就会远小于总数——筛选越严，通过率越低。这时会自动继续翻页补足；若接口/滚动都到底仍不够，说明在该搜索条件下“符合的职位”确实只有这么多，可放宽条件或换关键词再「多找一些」。
- **薪资筛了却没生效**：列表页读的是 DOM（乱码薪资解析不出会放行）。点「保存并筛选」或「多找一些」触发接口数据捕获后即可生效。
- **批量投递很慢**：正常，扩展刻意放慢间隔以降低风控；可在「设置 → 高级设置」调整间隔（但不得低于安全下限）。
- **聊天窗不在同页面**：如 BOSS 将聊天放到独立跨源 iframe/新页签，扩展无法跨源访问其内部 DOM。
